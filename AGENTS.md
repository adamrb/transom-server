# AGENTS.md

Guide for coding agents (and humans) working on **transom-server**. Read this before
changing anything. The user-facing documentation is [README.md](README.md); the whole pipeline,
end to end, is in [docs/end-to-end.md](docs/end-to-end.md).

## What this is

A self-hosted FastAPI service that receives recordings from the
[Transom Android app](https://github.com/adamrb/transom-android), transcribes them
(built-in engines or an external OpenAI-compatible endpoint), optionally summarizes and routes
them with an LLM, and hands results to the user's own automations via webhooks. It also serves
the React web dashboard and hosts the Android APK for in-app updates. Plaud's cloud is used for
one thing only: minting the SDK user token the recorder's encrypted BLE handshake requires.

## Layout

```
app/
  main.py            FastAPI app, every /api/v1 endpoint, auth middleware (docstring lists the API)
  config.py          Settings: every option is a PB_* environment variable (see .env.example)
  db.py              SQLite schema + MIGRATION_COLUMNS (additive column migrations)
  transcriber.py     Background transcription loop: engines -> cleanup -> summary -> export -> webhook
  engines/           STT engines behind one interface (base.py): local_whisper, parakeet, qwen3_asr,
                     openai_compat (remote worker), diarization (+ diarize_worker.py subprocess), enhance
  consensus.py       Multi-recognizer reconciliation for noisy audio
  cleanup.py         LLM transcript cleanup guarded by a vocabulary glossary
  router.py          AI routing: routes, deliveries, the LOCKED webhook payload contract
  formatting.py      Reader paragraphs (speaker turns, bookmarks; never per-segment timestamps)
  export.py          Markdown export (frontmatter + Summary / Highlights / Transcript)
  vocabulary.py      Custom vocabulary -> hotwords + alias corrections
  benchmark.py       `python -m app.benchmark` engine shootout CLI
  static/            Built dashboard (generated by `web/`; gitignored)
web/                 React 18 + TS strict + Vite + Tailwind v4 dashboard (own README.md)
contrib/agent-runner Optional webhook consumer that runs Claude Code / Codex via ACP (own README.md)
contrib/             Other optional helpers (vocabulary import from a notes vault)
tests/               pytest; `-m integration` marks tests that run real whisper-tiny inference
docs/                end-to-end.md
Dockerfile           CPU image (also builds the web dashboard)
Dockerfile.cuda      GPU image (diarization, Qwen3, optional custom CTranslate2 wheel from wheels-local/)
```

## Setup and everyday commands

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt -r requirements-stt.txt -r requirements-dev.txt
cp .env.example .env            # then set PB_AUTH_TOKENS at minimum
PB_DATA_DIR=./data PB_AUTH_TOKENS=dev uvicorn app.main:app --reload --port 8090

pytest -m "not integration"     # fast unit suite (what CI runs on every push)
pytest                          # also downloads whisper-tiny and runs real inference
cd web && npm ci && npm test && npm run build   # dashboard tests + build into app/static
docker compose up -d --build    # CPU deployment; see Dockerfile.cuda comments for GPU
```

Run the unit suite and the web tests before every commit. Both must be green.

## Rules that are not obvious from the code

- **Every setting is an environment variable with the `PB_` prefix**, declared in
  `app/config.py` and documented in `.env.example`. Adding a setting means updating both, plus
  the Configuration section of the README if it is user-facing.
- **Schema changes are additive.** Add columns through `MIGRATION_COLUMNS` in `app/db.py`; never
  rewrite or drop existing tables. Existing deployments upgrade in place with no manual step.
- **The webhook payload is a locked contract** (see the docstring in `app/router.py`). External
  consumers depend on it. Fields may be added, never renamed or removed.
- **The Android app is a client of this API.** Changing any `/api/v1` response shape or status
  code needs a matching change in the app, and older app versions must keep working: the app
  self-updates from this server, so the server is always upgraded first.
- **Transcripts are untrusted input.** Prompts that include a transcript wrap it in tags
  (`<transcript>` in the summarizer and router, `<primary>`/`<alternate>` in consensus) and tell
  the model not to follow instructions inside it. Keep that framing in any new LLM call.
- **Transcript readers never see per-segment timestamps.** Only bookmarks (recorder button
  presses) are jump points. Keep `formatting.build_paragraphs` as the single source of layout.
- **Security posture:** a configured bearer token (or a dashboard session minted by QR login)
  is full access. The middleware in `main.py` gates every path under `/api/` and `/v1/`; the
  exceptions are `/api/v1/health`, creating and polling a login request, and audio fetched with
  a signed link. Delivery result callbacks authenticate with a per-attempt scoped token instead.
  The dashboard shell, `/static`, `/docs` and `/openapi.json` are served without auth (they hold
  no data). `PB_TRUSTED_PROXIES` defaults to empty; never trust `X-Forwarded-For` without it.
- **No secrets, personal names, hostnames, or private paths in the repo.** Test fixtures use
  fictional names. Deployment specifics belong in `.env` (gitignored) or the user's own notes.
- **Naming.** The project is Transom. "Plaud" appears only to name the vendor's recorder, SDK,
  developer portal or cloud (nominative use); never in product names, package ids, image names
  or sample vocabulary (the samples use the fictional "Parrot Deck"). The `PB_` env prefix, the
  `pb_` user-id prefix and the `plaud-bridge.sqlite3` fallback in `config.db_path` are
  historical and kept so existing deployments upgrade in place.
- **Dependencies are pinned for a reason.** Read the comment above a pin (torch, starlette,
  CTranslate2) before changing it; several pins exist for old-GPU or security reasons.

## GPU and engine gotchas

- faster-whisper (CTranslate2) and torch-based pyannote cannot share one process: their cuDNN
  builds are ABI-incompatible, and once CTranslate2 holds a CUDA context the parent cannot fork.
  Diarization therefore runs in `engines/diarize_worker.py`, a long-lived subprocess spawned
  before whisper touches the GPU. Keep it that way.
- Never run two GPU transcriptions in parallel on a small card; the transcriber loop is
  deliberately serial. `PB_STT_MIN_FREE_VRAM_MB` drops engines to the CPU when the card is busy.
- `condition_on_previous_text` is auto-disabled when hotwords are set; with both on, long
  recordings loop into repeated phrases.
- Long remote jobs (worker mode behind a CDN or tunnel) stream Server-Sent Events keepalives,
  because proxies close idle connections and buffer plain JSON bodies.
- Pre-Pascal GPUs need a custom CTranslate2 wheel dropped into `wheels-local/` (gitignored);
  `Dockerfile.cuda` installs whatever is there.

## Releasing

1. Bump `VERSION` in `app/main.py` (reported by `/api/v1/health` and the OpenAPI schema), then
   tag `vX.Y.Z` on `main`.
2. `.github/workflows/release.yml` builds and pushes `ghcr.io/<owner>/transom-server`
   (`:latest` CPU and `-cuda:latest` GPU). If the repo variable `APK_RELEASE_URL` is set, the
   matching Android APK plus `manifest.json` is baked into the image so a fresh server hosts it.
3. The Android app's `versionCode` must increase for every APK hosted here; the server rejects a
   lower `version_code` upload with 409.

## When you change things

- Update `README.md` when behaviour or configuration changes, and `docs/end-to-end.md` when the
  pipeline's shape changes. Keep `.env.example` complete.
- Update this file when you add a module, a convention, or a gotcha future agents will need.
- Do not add per-user or per-deployment details (hostnames, vault layouts, model choices) to the
  repo; describe them as placeholders the way `docs/end-to-end.md` does.
